# Security 恢复笔记

## Last Session

- 新开了一个通用 `Security` 领域，用来承接计算机安全，而不是继续把安全散落在 AI、云原生、支付或游戏合规里。
- 第一版范围包括：网络安全、客户端安全、应用/API 安全、身份与访问、数据安全与隐私、云原生与基础设施安全、供应链安全、安全运营、治理风险合规、地区合规。
- 已建立 `专题总览 / 学习进度 / 恢复笔记 / 主题索引 / 地图索引 / 安全上帝视角全景架构图`。
- 继续补了第二层：`安全问题导航 / 安全决策导航 / 企业安全架构图 / 攻击面与控制点图 / 安全运营与事件响应闭环图 / 安全标准与法规索引`。
- 继续补了关键主题：`威胁建模 / 零信任架构 / 企业安全架构 / 安全工程与 DevSecOps / 漏洞管理与攻击面管理 / 密码学、密钥与证书基础 / 安全指标与成熟度模型`。

## What I Actually Understand Now

- 安全不是一个单点技术，而是一套围绕资产、攻击面、威胁、控制、检测、响应、恢复、治理和合规证明的系统。
- 网络安全只是其中一层；现代安全还必须覆盖身份、数据、应用、云、供应链、客户端和组织流程。
- 地区合规不应该孤立背法条，而应该放在 `数据类型 / 地区 / 行业 / 控制证据 / 审计责任` 的坐标里理解。
- 安全学习最怕碎片化，最好的入口是先看全景图，再按攻击面和控制面拆分。
- 第二层最重要的变化是：安全已经不只是“主题列表”，而是有了 `问题入口 -> 决策入口 -> 架构图 -> 控制点 -> 运营闭环 -> 合规标准` 的学习路径。
- 成熟安全能力不是工具堆叠，而是默认安全平台、可解释 release gate、持续检测、风险 owner、审计证据和事故复盘共同工作。

## What Still Feels Fuzzy

- 每条分支还需要更细的控制清单、真实案例和操作 playbook。
- 企业级安全架构、零信任、SOC、DevSecOps 和 GRC 已有入口，但需要后续补实施路线和成熟度检查表。
- 地区合规需要按美国、欧盟、中国、英国、东南亚等地区继续补官方来源摘记和更新机制。
- 安全面试专项还未建立。
